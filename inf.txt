
## O que é(resumo)
Um app Android de banco infantil (estudo pessoal) em Kotlin/Jetpack Compose que simula educação financeira para crianças, com cofrinho, metas de economia, missões, recompensas e ranking familiar. Dados persistem via Room Database + DataStore Preferences, login state sobrevive a restart, botão de reset restaura seed data.

### funções feitas
- Dados que antes morriam no reinicio do app agora persistem via Room SQLite
- Login state persiste via DataStore Preferences
- Reset button com confirmação restaura dados seed
- API pública do AppRepository inalterada — todos os 6 ViewModels funcionam sem modificação
- 5 Mutex removidos, syncCurrentUser bug fix aplicado

## Decisões chaves
| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Room como camada de persistência | Integração nativa Android Jetpack, suporte a Flow/Coroutines, type-safe queries | ✓ Good — 7 DAOs, 173 testes passando |
| DataStore Preferences para login state | Leve, key-value, Flow-based, sem overhead de banco relacional | ✓ Good — 2 campos, Flow<LoginPrefsData> |
| Seed via RoomDatabase.Callback.onCreate | Executa só na criação do banco (primeiro install) | ✓ Good — execSQL no onCreate |
| Reset via close() + deleteDatabase() + rebuild | Garante estado limpo idêntico ao primeiro install | ✓ Good — ResetSection + AlertDialog M3 |
| Entity dual-key pattern | uid (autoGenerate PK) + id (UUID seed) | ✓ Good — compatível com seed data existente |
| SharedFlow<RepositoryEvent> mantido | Eventos cross-entity com distinctUntilChanged | ✓ Good — complementa Room Flow |
| Não extrair interface do repositório | YAGNI — só 1 implementação | ✓ Good — ViewModels inalterados |
